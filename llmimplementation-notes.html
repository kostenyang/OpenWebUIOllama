離線安裝 — 已準備腳本,未實測

三段式:

  1. 有網機器跑 scripts/prepare-offline-bundle.sh /tmp/out → 抓 ollama-linux-amd64.tar.zst (1.2 GB) + zstd.deb + 從本機 /usr/share/ollama/.ollama/models/ 把 llama3.2:3b 的 manifest + blobs copy 出來

關鍵點:zstd 一定要先裝(focal minimal 沒裝),不然 tarball 解不開。

15:35 設計 + 寫 MCP offline scripts OK

觀察 /opt/vcf-mcp/ 結構:

  • Python 3.11 來自 uv(/root/.local/share/uv/python/cpython-3.11.15-...,96 MB)
  • venv 內含 50+ packages(pip list 跑不出來是因為 venv 用 uv 建的沒裝 pip,但 site-packages 都在)

根因:我寫 README 時順手在 systemd/ollama.service.override.conf 加了 OLLAMA_MODELS=/var/lib/ollama/models 當作「自訂模型位置」的範例,結果它就真的生效。Ollama 以 ollama user 跑,根本沒權限 mkdir /var/lib/ollama。

而且更糟:install-offline.sh 是把 blobs copy 到預設路徑 /usr/share/ollama/.ollama/models/,override 卻指到別的地方 — 就算建得起來 model 也找不到。

學到:offline 驗證的價值就在這 — online install 因為 install.sh 自己會 mkdir + chown,所以漏掉這個 mismatch 也跑得起來;到 fresh VM 才被抓到。沒驗證等於沒實作。

學到的

  • 同網段 clone running VM 是地雷:cloned VM 開機後 IP 撞,而且如果 source 就是你的 jump host(像 mcp-server)會把自己鎖在外面。用 template + customization spec 一次到位,別走 clone-then-fix 那條路。
  • pyvmomi 8.0+ 鎖 Python 3.10+:Ubuntu 20.04 / Python 3.8 上要 pip3 install 'pyvmomi<8.0'。
  • vCenter REST /api/vcenter/vm 不回 template(template=True 的 VM 不在 list)。要 list template 必走 SOAP / pyvmomi。
  • Ollama 2024 後改用 .tar.zst:Ubuntu 20.04 minimal 沒 zstd,install.sh 會明確報錯 — 不是神祕失敗。
  • Ollama 預設只 bind 127.0.0.1:不套 systemd override 任何外部主機都連不到。
  • FastMCP SSE session 會累積:長時間操作可能 trigger,看到 MCP tool 全 hang 就 systemctl restart vcf-mcp(會斷自己 SSE,等 1–3 分鐘 reconnect)。
  • 「文件寫得很完整」 ≠ 「真的能跑」:第一輪我把 OLLAMA_MODELS 寫進 override conf 當範例,線上裝因為 install.sh 會 mkdir + chown 所以沒事,offline 在 fresh VM 就馬上 crash loop。沒在 clean room 跑過的離線腳本約等於沒寫。
  • uv-managed Python 帶得走:不需要 reinstall packages 或裝 uv,把 /root/.local/share/uv/python/<version>/ 整包 tar 過去,目標機 untar 到同樣路徑就行(symlink 在 venv 裡是寫死路徑的,target 一定要一樣)。
  • self-signed cert SAN 要綁目標 IP:從別處 clone 過來的 cert SAN 還是寫源頭 IP,modern httpx / Python 3.10+ 不認 CN-only,連 curl --insecure 都會 verify 失敗。install 時用 openssl req -x509 ... -extensions v3 帶 [san] section 重生最穩。
